# MatchPulse-AI

منصة لعرض جدول مباريات كرة قدم حقيقي وتحليل احتمالي تفسيري. لا يَعِد المشروع بدقة 100% ولا يعرض النتيجة على أنها ضمان؛ كما لا ينبغي استخدام أي احتمال كأساس وحيد لقرار مالي أو مراهنة.

## ما تم بناؤه

تعرض الواجهة جدولًا للمباريات التي يعيدها مصدر `football-data.org`، مع الموعد والبطولة والفريقين والحالة. لكل مباراة زر يفتح نافذة OBTA تعرض احتمالات إرشادية ودرجة اكتمال البيانات والمنهجية. طبقة الاحتمالات الحالية `baseline-v1` تفسيرية وغير مدرّبة على بيانات تاريخية.

عند عدم ضبط مفتاح المصدر لا تعرض الواجهة مباريات وهمية، بل تظهر حالة واضحة تطلب إعداد المصدر. وعند فشل الشبكة، تبقى الصفحة قابلة للاستخدام وتوضح أن البيانات غير متاحة.

## تقويم المباريات المحددة (Pro)

تضيف الواجهة أداة **Pro Calendar** إلى مسار استعمال الجدول الفعلي:

1. اختر فريقًا أو أكثر في حقل **الفرق المفضلة** لتصفية الجدول الحقيقي.
2. حدّد المباريات الظاهرة التي تريدها.
3. اختر **تصدير المحدد إلى ICS · Pro**.

لا يرسل المتصفح مواعيد أو أسماء فرق ليتم الوثوق بها؛ يرسل معرفات المباريات والمرشحات فقط. يعيد الخادم جلب الجدول المجدول من المصدر الحقيقي، ويتأكد أن المعرفات ما زالت موجودة، ثم يبني ملف `text/calendar` من تلك البيانات وحدها. يكون `DTSTART` و`DTSTAMP` بتوقيت UTC وينتهي الملف بـ CRLF، كما تُهرّب أسماء الفرق والبطولات حسب ICS.

التصدير محمي في `POST /api/pro/calendar-export` ولا يفتح من الواجهة أو `localStorage` أو وسيط URL. قبل إنشاء الملف، يتحقق الخادم من هوية الحساب واشتراك `calendar_export` عبر خدمة استحقاق خادمية. يلزم أن تعيد الخدمة، بعد التحقق من جلسة/رمز المستخدم على الخادم، عقدًا مثل:

```json
{
  "subject": "stable-user-id",
  "entitlement": {
    "product": "calendar_export",
    "status": "active",
    "expiresAt": "2027-01-01T00:00:00.000Z",
    "cancelledAt": null,
    "revokedAt": null
  }
}
```

لا يسمح التصدير إلا إذا كان المنتج مطابقًا، والحالة `active`، والانتهاء مستقبليًا، ولم يُلغ أو يسحب الاستحقاق. تعني الاستجابات `401` أن الحساب غير موثق، و`403` أن الاستحقاق غير نشط، و`503 PURCHASE_SETUP_REQUIRED` أن خدمة الشراء/الاستحقاق لم تُعد بعد. هذه الحالة الأخيرة مقصودة وتفشل مغلقة؛ لا يوجد مستخدم تطوير أو مفتاح ثابت أو زر يمنح Pro.

### ما يزال معلقًا قبل الشراء داخل التطبيق

لا يوجد في هذا المستودع بعد حسابات أو قاعدة بيانات أو مزود تحصيل مهيأ. لذلك **لم يكتمل شراء اشتراك ولا يمكن تفعيل Pro تجاريًا**. بعد تحديد بلد التحصيل ومزود الدفع وقناة توزيع Android، يجب تنفيذ الآتي على الخادم قبل الإطلاق:

- ربط تدفق شراء من المزود الموافق عليه، أو Google Play Billing عندما تكون نسخة Android موزعة عبر Play وتنطبق قواعده.
- حفظ الربط الدائم بين الحساب ومعرف العميل والاشتراك وأحداث webhook الموقعة، مع معالجة قابلة لإعادة التسليم ومنع التفعيل المكرر.
- ربط `ENTITLEMENT_VERIFIER_URL` بخدمة تتثبت من هوية المستخدم وملكيته، والانتهاء والإلغاء والسحب، وتهيئة `ENTITLEMENT_VERIFIER_TOKEN` كسر خادم-إلى-خادم في بيئة النشر فقط.
- وصل طريقة مصادقة الواجهة بالتحقق الخادمي؛ لا يعد إرسال رمز من العميل وحده مصدر استحقاق.

لا تضع مفاتيح مزود البيانات أو مفاتيح الاستحقاق أو بيانات بطاقات في الواجهة أو Git.

## التشغيل

```bash
cp .env.example .env
# ضع FOOTBALL_DATA_TOKEN في بيئة الخادم فقط
npm start
```

افتح `http://localhost:8787`. يوفر الخادم `GET /api/health` و`GET /api/matches?status=SCHEDULED`، ويخفي مفتاح المصدر عن المتصفح.

## الاختبارات

```bash
npm run check
npm test
```

تختبر حزمة Node إنشاء ICS وUTC وCRLF والهروب، والتحقق من الإدخال، ومرشح الفرق المفضلة، وفشل الاستحقاق غير المهيأ، ومنع غير المستحق، والسماح فقط لمتحقق Pro محقون في الاختبار. اختبار `test:secret` اختياري ويتطلب `FOOTBALL_DATA_TOKEN` حقيقيًا وVitest مثبتًا؛ لا يُشغّل تلقائيًا ولا تستخدمه بمفتاح إنتاج غير مصرح به.

## البيانات والمنهجية

يستخدم الإصدار الأول عقدًا مع مصدر بيانات خارجي رسمي من خلال `FOOTBALL_DATA_TOKEN`. لا توجد مباريات أو نتائج مزروعة داخل المشروع. قبل تسمية نتائج التحليل بتوقعات إنتاجية ينبغي إضافة بيانات تاريخية مرخّصة، تقسيم زمني للتدريب والاختبار، معايرة احتمالات، وقياسات مثل Brier score وlog loss.

## الخصوصية والاستخدام المسؤول

لا يضع المشروع مفاتيح API في الواجهة أو Git. لا ينبغي استخدام الاحتمالات كضمان أو كأساس وحيد لقرار مالي أو مراهنة؛ النتائج الرياضية غير يقينية وقد تؤدي القرارات المبنية عليها إلى خسارة المال.
